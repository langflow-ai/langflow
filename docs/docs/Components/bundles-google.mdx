This page describes the components that are available in the **Google** bundle.

## BigQuery

Langflow integrates with [Google BigQuery](https://cloud.google.com/bigquery) through the **BigQuery** component in the [**Google** bundle](/bundles-google), allowing you to execute SQL queries and retrieve data from your BigQuery datasets.

### Use the BigQuery component in a flow

To use the **BigQuery** component in a flow, you need the following:

* A [Google Cloud project](https://developers.google.com/workspace/guides/create-project) with the BigQuery API enabled
* A [service account](https://developers.google.com/workspace/guides/create-credentials#service-account) with the **BigQuery Job User** role
* A [BigQuery dataset and table](https://cloud.google.com/bigquery/docs/datasets-intro)
* A [running Langflow server](/get-started-installation)

#### Create a service account with BigQuery access

1. Select and enable your Google Cloud project.
For more information, see [Create a Google Cloud project](https://developers.google.com/workspace/guides/create-project).
2. Create a service account in your Google Cloud project.
For more information, see [Create a service account](https://developers.google.com/workspace/guides/create-credentials#service-account).
3. Assign the **BigQuery Job User** role to your new account.
This role allows Langflow to access BigQuery resources with the service account.
You may also need to allow access to your BigQuery dataset.
For more information, see [BigQuery access control with IAM](https://cloud.google.com/bigquery/docs/access-control).
4. To generate a new JSON key for the service account, navigate to your service account.
5. Click **Add Key**, and then click **Create new key**.
6. Under **Key type**, select **JSON**, and then click **Create**.
A JSON private key file is downloaded to your machine.
Now that you have a service account and a JSON private key, you need to configure the credentials in the Langflow **BigQuery** component.

#### Configure credentials in the Langflow component

With your service account configured and your credentials JSON file created, follow these steps to authenticate the Langflow application.

1. Create a new flow in Langflow.
2. In <Icon name="Blocks" aria-hidden="true" /> **Bundles**, find the Google **BigQuery** component, and then add it to your flow.
3. In the **BigQuery** component's **Upload Service Account JSON** field, click **Select file**.
4. In the **My Files** pane, select **Click or drag files here**.
Your file browser opens.
5. In your file browser, select the service account JSON file, and then click **Open**.
6. In the **My Files** pane, select your service account JSON file, and then click **Select files**.
The **BigQuery** component can now query your datasets and tables using your service account JSON file.

#### Query a BigQuery dataset

With your component credentials configured, query your BigQuery datasets and tables to confirm connectivity.

1. Connect **Chat Input** and **Chat Output** components to the **BigQuery** component.

    ![BigQuery component connected to chat input and output](/img/integrations-bigquery.png)

2. Open the **Playground**, and then submit a valid SQL query.

    This example queries a table of Oscar winners stored within a BigQuery dataset called `the_oscar_award`:

    ```sql
    SELECT film, category, year_film
    FROM `big-query-langflow-project.the_oscar_award.oscar_winners`
    WHERE winner = TRUE
    LIMIT 10
    ```

## Google Generative AI

This component generates text using [Google Generative AI models](https://cloud.google.com/vertex-ai/docs/).

Supported models include the Gemini 1.5, 2.0, 2.5, and 3.0 series. The latest Gemini 3.0 models (`gemini-3-pro-preview`, `gemini-3-flash-preview`, and `gemini-3-pro-image-preview`) offer advanced reasoning and multimodal capabilities.

### Google Generative AI parameters

| Name | Type | Description |
|------|------|-------------|
| Google API Key | SecretString | Input parameter. Your Google API key to use for the Google Generative AI. |
| Model | String | Input parameter. The name of the model to use, such as `"gemini-2.5-flash"` or `"gemini-3-pro-preview"`. |
| Max Output Tokens | Integer | Input parameter. The maximum number of tokens to generate. |
| Temperature | Float | Input parameter. Run inference with this temperature. |
| Top K | Integer | Input parameter. Consider the set of top K most probable tokens. |
| Top P | Float | Input parameter. The maximum cumulative probability of tokens to consider when sampling. |
| N | Integer | Input parameter. Number of chat completions to generate for each prompt. |
| model | LanguageModel | Output parameter. An instance of ChatGoogleGenerativeAI configured with the specified parameters. |

## Google Generative AI Embeddings

The **Google Generative AI Embeddings** component connects to Google's generative AI embedding service using the GoogleGenerativeAIEmbeddings class from the `langchain-google-genai` package.

For more information about using embedding model components in flows, see [Embedding model components](/components-embedding-models).

### Google Generative AI Embeddings parameters

| Name | Display Name | Info |
|------|--------------|------|
| api_key | API Key | Input parameter. The secret API key for accessing Google's generative AI service. Required. |
| model_name | Model Name | Input parameter. The name of the embedding model to use. Default: "models/text-embedding-004". |
| embeddings | Embeddings | Output parameter. The built GoogleGenerativeAIEmbeddings object. |

## Google Workspace actions

The **Google Workspace** action components run Gmail, Drive, and Calendar operations
against a [managed connection](/connection-oauth) instead of a pasted token. The
connection stores the OAuth credential in encrypted server-side storage, refreshes it in
the worker that uses it, and never places a token in flow JSON.

| Component | Action | Scope requested |
|---|---|---|
| **Gmail: Send Email** | `users.messages.send` from the connected mailbox | `https://www.googleapis.com/auth/gmail.send` |
| **Drive: List Files (app files)** | `files.list` | `https://www.googleapis.com/auth/drive.file` |
| **Drive: Fetch File (app files)** | `files.get` plus `files.export` for Google-native documents | `https://www.googleapis.com/auth/drive.file` |
| **Calendar: List Events** | `events.list` | `https://www.googleapis.com/auth/calendar.events.readonly` |
| **Calendar: Create Event** | `events.insert` | `https://www.googleapis.com/auth/calendar.events` |

Each component requests exactly one scope, the one its action needs. No component asks
for a scope Google classifies as restricted, so the Langflow-managed OAuth app does not
require a security assessment.

### Drive reach on the drive.file scope

`drive.file` is a non-sensitive scope that grants access **only to files this application
created, or that the user explicitly opened with it**. The rest of the user's Drive is
invisible to the listing and fetch components, so an empty listing is a normal result for
a correctly configured connection rather than an error. Reaching arbitrary Drive content
requires a restricted scope, which is deliberately out of scope for this release.

### Connect a Google account

1. Configure a Google registration on the server. See
   [Configure connection OAuth](/connection-oauth).
2. Create the connection record:

    ```http
    POST /api/v1/connections
    Content-Type: application/json

    {"provider_key":"google","name":"work","display_name":"Google (work)",
     "ownership_mode":"user","executing_identity":{"identity":"user_delegated"},
     "allow_non_interactive":false}
    ```

3. Start consent from the same authenticated browser, requesting only the scopes the
   actions in your flow need:

    ```http
    POST /api/v1/connections/CONNECTION_ID/oauth/start
    Content-Type: application/json

    {"registration_id":"google-work",
     "scopes":["https://www.googleapis.com/auth/gmail.send"]}
    ```

4. Navigate to the returned `authorization_url` and complete consent.
5. In the flow, set the component's **Google Connection** field to the handle
   `google/work`.

Verify the grant with `POST /api/v1/connections/CONNECTION_ID/test`. A connection that is
missing a scope fails the action with a `scope-missing` error rather than a partial result.

### Sending attachments

**Gmail: Send Email** attaches local files by path. On a deployment that sets
`LANGFLOW_RESTRICT_LOCAL_FILE_ACCESS`, an attachment path must resolve inside the
authenticated user's or executing flow's storage directory, the same containment the
built-in file components apply; a path outside it is refused before the file is read.
On a single-tenant deployment, where the restriction is off by default, any readable
path is attached.

**Calendar: Create Event** exposes **Conference Data Version** because the capability
matrix lists it. It only tells Calendar whether to honour a `conferenceData` block in the
request; this component never sends one, so setting it to `1` does not by itself add a
Meet link to the event.

### Error behavior

Every action maps provider failures onto a stable, sanitized vocabulary: `auth-expired`
when the credential is rejected (retried once against a freshly minted token before
surfacing), `scope-missing` on a Google `403` that is not a rate limit, `rate-limited` on
`429` and on `403` quota reasons, and `provider-unavailable` on `5xx`. Google response
bodies are never passed through verbatim.

### Knowledge-base ingestion from Drive

The **Google Drive** knowledge-base ingestion source reads the same
`drive.file` scope through the same managed connection, so a knowledge base can be
kept in sync with the files this application created or the user opened with it.
Configure it with a connection handle:

```json
{"source_type": "google_drive", "source_config": {"connection": "google/work", "folder_id": "FOLDER_ID"}}
```

Google-native documents are exported on the way in: Docs and Slides as plain
text, Sheets as CSV. Folders, Forms, Sites, and shortcuts are skipped because
they carry no text to ingest.

Because ingestion runs as a background job rather than an interactive request,
the connection must have been created with `allow_non_interactive` set. Without
it the run fails with `connection-not-authorized`, which is the intended
behavior: a scheduled job acting on a user's Drive is something that user opts
into explicitly.

:::important
The source is not registered by default in this release. It resolves its
connection under a `job_owner` execution principal, and background jobs do not
carry an execution principal yet, so every resolution would fail closed. Set
`LANGFLOW_KB_GOOGLE_DRIVE_ENABLED=true` on a build that carries the
executing-identity work to opt in.
:::

### Swapping an action to a different substrate

All five actions run on the Google Python SDK today. If a future release moves one of them
to a different substrate — for example an MCP-backed Gmail send — the swap is contained by
the capability manifest at
`src/bundles/google/src/lfx_google/components/google/capabilities.v1.json`:

1. Change the capability's `substrate` value and, if the new path needs different scopes,
   its `required_scopes`. Leave its `id`, `policy_keys`, `component_ref`, and
   `display_name` untouched so saved flows, operator policy, and the palette do not move.
2. Reimplement the component's output method against the new substrate. The component
   class name and its input and output names are the compatibility surface and must not
   change; nothing else in the component is.
3. Re-record the contract fixtures for that action and rerun
   `pytest src/bundles/google/tests`. The manifest test asserts the manifest still matches
   the capability matrix, so a scope change has to be made in
   `design/dedicated-integrations/matrices/google.json` first.
4. Ship it as a bundle minor version through
   `python scripts/ci/bundle_release_plan.py update`. No Langflow release is required.

## Legacy Google components

The following Google components are in legacy status:

<details>
<summary>Google OAuth Token</summary>

The **Google OAuth Token** component was deprecated in Langflow 1.4.0 and is hidden from the
component palette. It runs a local-server OAuth flow, which cannot complete on a server
deployment, and it puts a long-lived credential into flow data. Running it logs a
deprecation warning.

To connect your flows to Google services, use a [managed connection](/connection-oauth) with
the [Google Workspace action components](#google-workspace-actions), or
[Composio components](/bundles-composio).

</details>

<details>
<summary>Gmail Loader</summary>

This component loads emails from Gmail using label ID filters and either a
[managed connection](/connection-oauth) or
[Service Account JSON](https://developers.google.com/identity/protocols/oauth2/service-account)
credentials. Set exactly one of the two.

Adding the connection field changed these components' code, so a flow saved before
Langflow 1.13 shows the ordinary "update available" prompt on the loader node. The update
is additive — the checker classifies it `outdated_safe`, never breaking — and the flow runs
unchanged whether or not you take it.

The optional **Google Connection** field requires the restricted `gmail.readonly` scope.
The Langflow-managed hosted and Desktop OAuth apps never request restricted scopes, so this
field only resolves against a **self-managed, customer-owned** registration whose scope
ceiling includes `gmail.readonly`. It is not exposed as a Google capability for policy or
discovery.

As an alternative, you can use [Composio components](/bundles-composio) to connect your flows to Google services.

</details>

<details>
<summary>Google Drive Loader</summary>

This component loads a single document from Google Drive using a document ID and either a
[managed connection](/connection-oauth) or
[Service Account JSON](https://developers.google.com/identity/protocols/oauth2/service-account)
credentials. Set exactly one of the two. A managed connection resolves on `drive.file`, so it
reaches only files this application created or the user opened with it.

For new flows, use [**Drive: Fetch File (app files)**](#google-workspace-actions).

</details>

<details>
<summary>Google Drive Search</summary>

This component searches Google Drive using [Service Account JSON](https://developers.google.com/identity/protocols/oauth2/service-account) credentials and various query strings and filters.

The connection-backed replacement is [**Drive: List Files (app files)**](#google-workspace-actions).
It runs on `drive.file`, which is a narrower reach than a pasted token may have had: it lists
only files this application created or the user opened with it.

</details>
