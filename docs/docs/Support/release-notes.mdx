This page summarizes significant changes to Langflow in each release.
For all changes, see the [Changelog](https://github.com/langflow-ai/langflow/releases/latest).

Due to strict SemVer requirements, Langflow Desktop can have different patch versions than the core Langflow OSS Python package, but the major and minor versions are aligned.

## Prepare to upgrade

For an existing 1.11.x Python installation, follow [Upgrade from Langflow 1.11.x](/get-started-installation#upgrade-from-langflow-111).
An in-place package upgrade can retain incompatible optional providers from the old full installation.
The procedure uses a new environment with the `bundles` extra and preserves the instance's database, encryption key, files, and knowledge storage.
Keep backups taken before the first new-version startup so you can restore them if needed.

:::warning
Whenever possible, the Langflow team recommends installing new Langflow versions in a new virtual environment or VM before upgrading your primary installation.
This allows you to [import flows](/concepts-flows-import#import-a-flow) from your existing installation and test them in the new version without disrupting your existing installation.
In the event of breaking changes or bugs, your existing installation is preserved in a stable state.
:::

To avoid the impact of potential breaking changes and test new versions, the Langflow team recommends the following upgrade process:

1. Recommended: [Export your projects](/api-projects#export-a-project) to create backups of your flows:

    ```bash
    curl -X GET \
    "$LANGFLOW_SERVER_URL/api/v1/projects/download/$PROJECT_ID" \
      -H "accept: application/json" \
      -H "x-api-key: $LANGFLOW_API_KEY"
    ```

   To export flows from the visual editor, see [Import and export flows](/concepts-flows-import).

2. Install the new version:

   * **Langflow OSS Python package**: Install the new version in a new virtual environment. For instructions, see [Install and run the Langflow OSS Python package](/get-started-installation#install-and-run-the-langflow-oss-python-package).
   * **Langflow Docker image**: Run the new image in a separate container, or upgrade your existing image. For more information, see [Upgrade the Langflow Docker image](/deployment-docker#upgrade-the-langflow-docker-image).
   * **Langflow Desktop**: To upgrade in place, open Langflow Desktop, and then click **Upgrade Available** in the Langflow header. If you want to isolate the new version, you must install Langflow Desktop on a separate physical or virtual machine, and then [import your flows](/concepts-flows-import) to the new installation.

3. [Import your flows](/concepts-flows-import) to test them in the new version, [upgrading components](/concepts-components#component-versions) as needed.

    When upgrading components, you can use the **Create backup flow before updating** option if you didn't previously export your flows.

4. If you installed the new version in isolation, upgrade your primary installation after testing the new version.

    If you made changes to your flows in the isolated installation, you might want to export and import those flows back to your upgraded primary installation so you don't have to repeat the component upgrade process.

## 1.14.x

Highlights of this release include the following changes. For all changes, see the [Changelog](https://github.com/langflow-ai/langflow/releases/latest).

### Deployment variables

Set `LANGFLOW_DEPLOYMENT_TYPED_VARIABLES_ENABLED=true` to include secret and plain variable declarations in version 7 deployment artifacts.
The destination must support this format. Packages carry names and kinds without source values, and packaging refuses unresolved kinds.
For details, see [Deployment variable declarations](/environment-variables#deployment-variable-declarations).

When an extension binds a deployment to an execution account, unresolved MCP variable placeholders fail before an outbound connection.
Restarting an instance also preserves existing empty assistant variables instead of adding duplicate default rows.

### New features

- Connections

    Langflow 1.14 includes new persistent connections to Jira Cloud, GitHub, GitLab, Confluence Cloud, ServiceNow, Telegram, and WhatsApp Business accounts.
    For more information, see [Connections](./connections).

- Secret-key audit and rotation

    The Langflow CLI command `langflow secrets audit` reads stored encrypted values, and `langflow secrets rotate` rewraps the secret values under a new root key.
    For more information, see [langflow secrets audit](./configuration-cli#langflow-secrets-audit) and [langflow secrets rotate](./configuration-cli#langflow-secrets-rotate).

## 1.13.x

Highlights of this release include the following changes. For all changes, see the [Changelog](https://github.com/langflow-ai/langflow/releases/latest).

### Breaking changes

- Official packages require authentication by default

    Official Python packages, tagged source archives, and Docker images now set `LANGFLOW_AUTO_LOGIN=false`.
    Set `LANGFLOW_SUPERUSER_PASSWORD`, then sign in as `langflow` or the username in `LANGFLOW_SUPERUSER`.

    Before upgrading an auto-login installation, [prepare that account for password sign-in](/api-keys-and-authentication#upgrade-from-auto-login).

    If you already upgraded and can't sign in, see [recover access](/troubleshoot#recover-access-after-upgrading).

    For more information, see [API keys and authentication](/api-keys-and-authentication#langflow-auto-login).

- Project MCP and A2A endpoints require authentication by default

    In 1.13.2, new projects default to API-key authentication, including auto-login installations.
    Existing projects with unset authentication settings adopt that default at startup.
    When `LANGFLOW_AUTO_LOGIN=false`, startup also changes projects set to **None** to API-key authentication.

    Update existing MCP clients with the configuration from the project's **MCP Server** tab.
    For protected A2A requests, send the flow owner's Langflow API key in the `x-api-key` header.
    Public A2A agent-card discovery remains available without credentials.

    See [MCP authentication](/mcp-server#authentication) and [A2A authentication](/a2a-server#authentication) for client setup and the supported public-project and superuser exceptions.

- MCP shell wrappers require a separate inline command

    Stored MCP shell configurations must place the inline command in the argument following `-c`.
    Replace `["-cuvx mcp-proxy"]` with `["-c", "uvx mcp-proxy"]`.
    Direct script operands and shells without an inline command are rejected even when interpreter hardening is disabled.
    Login, interactive, verbose, and xtrace modes are also rejected.

- Chroma and Local DB components are removed

    Langflow 1.13 stores local Knowledge and Memory in SQLite, instead of a local Chroma database.
    The [**Chroma DB**](/components-bundle-components#legacy-bundles) and [**Local DB**](/components-bundle-components#legacy-bundles) components are legacy.

    Replace **Chroma** and **Local DB** with a [knowledge base](/knowledge#knowledge-bases), or with a supported remote vector store.

    For more information, see [Upgrade Knowledge and Memory storage](/knowledge-storage-upgrade).

- Python components require keyword class patterns

    Positional class patterns such as `case Point(x, y)` are no longer accepted in Python Interpreter, Python REPL, or Lambda Filter code, including saved flows.
    Use keyword patterns such as `case Point(x=x, y=y)`.
    This restriction also applies to builtin positional patterns such as `case int(n)`.

- Repeated ingestion uses stable chunk IDs

    In 1.13.2, repeated ingestion uses stable chunk IDs.
    The first re-ingestion of data created before this fix can add one stable-ID copy per chunk.
    Updating a document's content leaves its previous chunks in place.

### New features

- Audit logging

    Set `LANGFLOW_AUDIT_ENABLED=true` to record an append-only history of flow and project operations, including who attempted a change, on which resource, when, how it completed, and a description of what was written.
    Query events with `GET /api/v1/flows/audits` and `GET /api/v1/projects/audits`.

    For more information, see [Audit logging](./audit-logging).

- Connections

    Langflow stores Google Workspace, Microsoft 365, and Slack accounts as persistent connections.
    For more information, see [Connections](./connections).

- Concurrent editing

    Langflow now protects a flow that is open by more than one user.
    For more information, see [Concurrent editing](./concurrent-editing).

- Instance migration

    Langflow provides a guided workflow to migrate users, projects, flows, settings, local files, and local knowledge bases to a new instance.
    The workflow checks the source instance, pauses writes, creates a backup, copies applicable data to the target instance's storage, verifies the copy, and provides recovery steps.

    For more information, see [Migrate a Langflow instance](/instance-migration).

- Administration API and CLI

    Superusers can manage users, teams, and roles with the API or the `langflow admin` command.
    For more information, see [Administer users and teams with the API and CLI](./admin-api-cli).

## Component changes

- The ALTK component is removed

    The [**ALTK**](/components-bundle-components) component is removed.

    Replace **ALTK** with the [**Agent**](/components-agents) component.

- MrScraper components are removed

    The [**MrScraper**](/bundles-mrscraper) bundle now provides three components.

    Instead, use the **Scraper API** or **Web Search** components.

    For more information, see [Update existing flows](/bundles-mrscraper#updating-existing-flows).
