Many third-party APIs now sell access **per call** over the `x402` scheme.
When your agent calls such an API without payment, the server responds with
`402 Payment Required` and a small JSON body describing what it costs.
Your agent can read that price, authorize a payment, and retry the same
request to get the result — no account signup, no API key, no subscription.

This tutorial shows you how to build a Langflow custom component that makes a
pay-per-call API request and completes the `402` handshake, so your agents can
buy tool access in flow instead of stopping at every paid endpoint.

## How x402 works

`x402` is a request-for-payment pattern. A server that offers a paid endpoint
answers an unpaid request like this (v2 envelope):

```http
HTTP/1.1 402 Payment Required
Content-Type: application/json
PAYMENT-REQUIRED: v2; scheme=exact; network=nano; asset=XNO; amount=1200000000000000000000000000000; payTo=nano_1...

{
  "reason": "Payment required",
  "accepts": [
    {
      "scheme": "exact",
      "network": "nano",
      "asset": "XNO",
      "amount": "1200000000000000000000000000000",
      "decimals": 30,
      "payTo": "nano_1..."
    }
  ]
}
```

The `accepts[]` array lists the payment methods the seller accepts, and the
`PAYMENT-REQUIRED` header (v2) carries the same requirement so a client can
read it without parsing the body. The caller picks one method, creates the
payment to the listed `payTo` address, and retries the original request with a
proof header. The flow is documented by the [x402 specification](https://x402.org)
and by sellers and wallets such as [OpenSea's x402 docs](https://docs.opensea.io/docs/x402)
and [MetaMask's explainer](https://www.metamask.io/news/what-is-x402).

## Build a custom component that handles a `402`

In Langflow, a custom component is a Python class that inherits from the
[`Component`](/contributing-components) base class. Create a new component that:

1. Makes an HTTP request to the paid endpoint.
2. Detects a `402 Payment Required` response and reads the `accepts[]` payment
   requirements from the body.
3. If a payer is configured, completes the payment and retries the request
   before returning a result.
4. Fails cleanly — **no money moves** — if the response is malformed or no payer
   is configured.

A self-contained Langflow component that handles a `402` — reads the payment
requirement from the body's `accepts[]` array or the v2 `PAYMENT-REQUIRED`
header, completes the payment when a value is returned, and never moves money on
a malformed response:

```python
import json
import httpx
from lfx.custom.custom_component.component import Component
from lfx.io import MessageTextInput, Output


def _read_accepts(resp: httpx.Response) -> list:
    """Return the payment requirements from a 402, body-first then v2 header."""
    body_accepts = []
    try:
        body = resp.json()
        if isinstance(body, dict):
            body_accepts = body.get("accepts") or []
    except (ValueError, json.JSONDecodeError):
        pass  # non-JSON body; fall back to the header

    hdr = resp.headers.get("PAYMENT-REQUIRED", "")
    if isinstance(body_accepts, list) and body_accepts:
        return body_accepts
    if hdr.startswith("v2"):
        try:
            params = dict(
                (k.strip(), v.strip())
                for k, v in (p.split("=", 1) for p in hdr.split(";")[1:] if "=" in p)
            )
            return [params]
        except ValueError:
            return []
    return body_accepts if isinstance(body_accepts, list) else []


class PaidApiCaller(Component):
    display_name: str = "Paid API Caller"
    description: str = "Call a pay-per-call (x402) API and complete the 402 payment handshake."
    icon: str = "credit-card"

    inputs = [
        MessageTextInput(name="url", display_name="Endpoint URL"),
        MessageTextInput(
            name="payment_proof",
            display_name="Payment proof (optional)",
            tool_mode=True,
            info="A payment header from your x402 wallet (v1 X-PAYMENT / v2 "
                 "PAYMENT-SIGNATURE). When omitted the component returns the "
                 "payment requirement without spending.",
        ),
    ]

    outputs = [
        Output(display_name="Result", name="result", method="call_api"),
    ]

    def call_api(self):
        # First attempt: unpaid request.
        resp = httpx.get(self.url)

        # Not a 402: return the response as-is.
        if resp.status_code != 402:
            return resp.text

        # 402: read the payment requirements (body accepts[] or v2 header).
        accepts = _read_accepts(resp)
        if not accepts:
            return "Payment required, but the 402 response carried no valid x402 requirement."

        if not self.payment_proof:
            # No proof to retry with: return the requirement so the caller
            # knows what to pay. No money moves on this path.
            return f"Payment required. Accepts: {accepts}"

        # Retry the original request with the payment proof header.
        retried = httpx.get(
            self.url,
            headers={"PAYMENT-SIGNATURE": self.payment_proof, "X-PAYMENT": self.payment_proof},
        )
        return retried.text
```

To *create* the `payment_proof` value, use a MIT-licensed x402 payment client
such as [`feeless402`](https://pypi.org/project/feeless402/) (`pip install
feeless402; nano-pay init`). It signs a Nano send block locally, returns the
v1 `X-PAYMENT` / v2 `PAYMENT-SIGNATURE` header value, and — with `prework`
— keeps steady-state payments sub-second. The canonical [x402 reference
client](https://github.com/coinbase/x402) documents the same pattern.

x402 is rail-agnostic — the `accepts[]` envelope names a scheme, network and asset. A feeless, instant rail like Nano (XNO) keeps sub-cent per-call payments practical for both the tool seller and the agent buyer, with no gas and no merchant account. But the pattern works the same for any rail the seller lists.
