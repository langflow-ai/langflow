Langflow uses installation-scoped telemetry and pseudonymous authenticated product-usage telemetry to collect
statistics about feature usage and performance.
The Langflow team uses this data to identify popular features and areas that need improvement based on actual usage patterns.
This helps prioritize development efforts on the most impactful changes and popular features.

## Privacy

The Langflow team respects your privacy, and the team is committed to protecting your data.

Langflow telemetry doesn't send raw operating-system or authenticated Langflow user names, or raw authenticated user IDs.
Authenticated product-usage IDs are derived from the installation identifier and the user's random database UUID.
Usernames and SSO email addresses are not used to derive these IDs, and the same user UUID produces different IDs
on different installations. Free-form error messages are omitted from outgoing telemetry because they can contain
user inputs, SQL parameters, or credentials. Error types, stack hashes, success flags, and timings are retained.
The data collected by each event, including fields that can contain user-provided values, is documented below.

Product-usage events are delivered through Segment. Langflow generally uses a persistent anonymous installation
identifier and doesn't send operating-system user names or raw authenticated Langflow user IDs. Desktop email
registration events use a fresh one-time identifier instead, so the registered address cannot be linked to the
installation's other telemetry.

## Configure Segment

Official Langflow release artifacts send product-usage events to the approved production Segment source by default.
The production write key is injected from a protected secret while building the release artifact and isn't stored in
the source repository. Source checkouts don't send telemetry unless `LANGFLOW_SEGMENT_WRITE_KEY` is set. The same
variable overrides the release default, such as when validating a development source. To use a compatible Segment
endpoint, set `LANGFLOW_SEGMENT_API_URL`; it defaults to `https://api.segment.io/v1/track`.

Use separate write keys for test and production sources.

Every Segment event includes the IBM Common Schema product properties `UT30: 30AS5`, `productCode: WW3151`,
`productCodeType: WWPC`, `productPlanName: opensource`, `productPlanType: freemium`, and `productTitle: Langflow`.
Except for Desktop email registration events, the persistent installation identifier is used for `anonymousId`,
`properties.instanceId`, and `properties.subscriptionId`. Each email registration event uses a fresh UUID for these
three fields and omits `userId`.

For authenticated requests, the top-level `userId` is `lf-user-` followed by the SHA256 hash of the installation
identifier, a separator, and the user's random database UUID. Langflow captures this opaque ID before handing an event
to the telemetry worker. Lifecycle events and standalone LFX events use `lf-` followed by the SHA256 hash of the
installation identifier.
The shared default `langflow` account and unauthenticated webhook callers also use this installation fallback.
Background workflow jobs retain only the opaque telemetry user ID and restore it during execution and resume.
Jobs saved with the previous username-hash scheme use installation fallback when resumed.

Free-form error messages are removed at the outbound telemetry boundary. Events retain success flags, exception types,
exception contexts, stack trace hashes, and structured integration error codes without exporting user input, stored
values, SQL statements, or parameters that an error message might contain.

## Opt out of telemetry

To opt out of telemetry, set `DO_NOT_TRACK=True` in your [Langflow environment variables](/environment-variables) before starting Langflow. This disables telemetry data collection.

## Data that Langflow collects

Langflow telemetry collects data on flow runs, your environment, and component usage.
Events use the IBM Common Schema names `Started Process`, `Ended Process`, `Ran Process`, and `UI Interaction`.
The original Langflow event category is included in the Common Schema `object` property. Process events also include
the required `processType` property.

### Run

This telemetry event is sent every time a flow is executed.

- **IsWebhook**: Indicates whether the operation was triggered with a webhook.
- **Seconds**: Duration in seconds for how long the operation lasted, providing insights into performance.
- **Success**: Boolean value indicating whether the operation was successful, helping identify potential errors or issues.

### Shutdown

This telemetry event captures information about application lifecycle and runtime duration.

- **TimeRunning**: Total runtime before shutdown, which is useful for understanding the application lifecycle and optimizing uptime.

### Version

This telemetry event is sent once when the telemetry service starts.

- **Version**: The specific version of Langflow used, which helps in tracking feature adoption and compatibility.
- **Platform**: Operating system of the host machine, which helps determine the most popular platforms for development and testing efforts.
- **Python**: The version of Python used, assisting in maintaining compatibility and support for various Python versions.
- **Arch**: Architecture of the system, such as x86 or ARM, which helps prioritize hardware optimization and testing in the Langflow codebase.
- **AutoLogin**: Indicates whether the auto-login feature is enabled, reflecting user preference settings.
- **CacheType**: Type of caching mechanism used, which impacts performance and efficiency.
- **BackendOnly**: Boolean indicating whether Langflow is running in backend-only mode, useful for understanding deployment configurations.
- **DatabaseDialect**: The database engine Langflow is configured to use, such as `sqlite` or `postgresql`. Only the engine name is sent, never the database URL, host, or credentials.
- **Desktop**: Indicates whether Langflow is running in desktop mode (Langflow Desktop), helping to understand usage patterns across different deployment types.

### Email

This telemetry event is sent to track registered email addresses for Langflow Desktop. The event is triggered in two cases:

* Every time a new email address is registered through the POST `/api/v2/registration/` endpoint.
* Each time you start Langflow Desktop _after_ an email address is registered.

   The first time you start Langflow Desktop and register your email address, the event is reported by the call to the POST `/api/v2/registration/` endpoint.

This telemetry event includes the following information:

- **Email**: The registered email address, which helps track user registrations and facilitate an understanding of the Langflow Desktop user base.
- **ClientType**: Indicates the client type, which can be "desktop" or "oss".

If telemetry is disabled with the `DO_NOT_TRACK` environment variable in Langflow Desktop, you are still prompted to enter your email address, but the email address is stored in your local Langflow database only.

### Playground

This telemetry event monitors performance and usage patterns in the **Playground** environment.

- **Seconds**: Duration in seconds for **Playground** execution, offering insights into performance during testing or experimental stages.
- **ComponentCount**: Number of components used in the **Playground**, which helps understand complexity and usage patterns.
- **Success**: Success status of the **Playground** operation, aiding in identifying the stability of experimental features.

### Component

This telemetry event is sent for each component execution.

- **Name**: Identifies the component, providing data on which components are most utilized or prone to issues.
- **Seconds**: Time taken by the component to execute, offering performance metrics.
- **Success**: Whether the component operated successfully, which helps in quality control.

### Component inputs

This telemetry event is sent alongside each component execution.
It is joined to the Component event through the component run ID.

By default, Langflow does not send component input values in telemetry.
Only these field types are tracked:

- Integer and float numbers
- Booleans
- Dropdown selections
- Tab selections

Free-text fields such as prompts, messages, code, and multiline text are never tracked.
Password, file, auth, connection, and MCP configuration fields are never tracked.

- **ComponentRunId**: Unique identifier for the component run, used to join this event with the Component event.
- **ComponentId**: Identifier for the component instance.
- **ComponentName**: Name of the component.
- **ComponentInputs**: Dictionary of input names and their configured values.
- **ChunkIndex**: Index of the chunk when a large payload is split to respect size limits.
- **TotalChunks**: Total number of chunks when a large payload is split.

### Component index

This telemetry event is sent when Langflow loads the component index at startup.
It reports aggregate metrics such as module and component counts and load time.
It does not include user or flow data.

### Exception

This telemetry event is sent when an unhandled exception is captured by Langflow's lifecycle or global exception handler.

- **Type**: The exception class name, such as `ValueError`.
- **Context**: Additional contextual information related to where the exception occurred, such as route, component, or operation details, when available.
- **StackTraceHash**: A hash of the stack trace used to group similar exceptions for easier analysis.

### Deployment provider

This telemetry event is sent for various lifecycle operations on deployment provider accounts, such as create, delete, and update.

- **DeploymentAction**: The specific action performed, such as `provider.create` or `provider.delete`.
- **DeploymentProvider**: The deployment provider used, such as `watsonx-orchestrate`.
- **DeploymentSeconds**: Duration in seconds for the operation, providing performance insights.
- **DeploymentSuccess**: Boolean value indicating whether the operation was successful.
- **WxoTenantId**: A unique identifier for the tenant, populated only for `watsonx-orchestrate` deployments, used to understand multi-tenant usage patterns without collecting personal information.

### Deployment

This telemetry event is sent for various lifecycle operations on deployment resources, such as create, delete, and update.

- **DeploymentAction**: The specific action performed, such as `deployment.create`.
- **DeploymentProvider**: The deployment provider used, such as `watsonx-orchestrate`.
- **DeploymentSeconds**: Duration in seconds for the operation, providing performance insights.
- **DeploymentSuccess**: Boolean value indicating whether the operation was successful.
- **WxoTenantId**: A unique identifier for the tenant, populated only for `watsonx-orchestrate` deployments, used to understand multi-tenant usage patterns without collecting personal information.
