Langflow and LFX are versioned together on the same `major.minor` line, so you can always tell which LFX release runs which flows.

## Compatibility contract

**LFX `X.Y.N` is guaranteed compatible with any flow exported from Langflow `X.Y.M`.**

The major and minor numbers must match.
The patches `.N` for LFX and `.M` for Langflow are released independently. An LFX patch fix does not require a Langflow patch release, and vice versa.

When LFX and a flow share the same `major` version but differ on `minor`, such as a flow exported from Langflow 1.13.x run with LFX 1.14.x, individual components may have been updated since the flow was saved.
Use `lfx upgrade` to check compatibility and apply safe automatic fixes before running or serving such a flow.

## Check and upgrade flows with `lfx upgrade`

The `lfx upgrade` command inspects a flow against the built-in component registry and reports any components that have become incompatible or that have safe automatic upgrades available.

`lfx upgrade` compares each component in the flow against a bundled index at `_assets/component_index.json` that ships with the LFX release.

To check every flow saved in a Langflow server's database before you upgrade the server, use [`langflow upgrade-check`](../Deployment/upgrade-check.mdx).

Run it with no flags to get a read-only compatibility report. The command reads your flow JSON, walks through every component node, and prints one line per node with its status. It does not modify the file.

```bash
lfx upgrade my-flow.json
```

Example output:

```text
  [SAFE] Agent (AgentComponent) - id: abc123
  [OK] Chat Output (ChatOutput) - id: def456
```

| CLI output | What it means | Example |
|---|---|---|
| `[OK]` | Component matches the current registry. | No action needed. |
| `[SAFE]` | Component code changed, and updating the component keeps every connection and saved value in your flow. `lfx upgrade --write` can apply this update automatically. | An output that previously emitted only `Message` now also supports `Data`, or the component gained an output or an optional input. |
| `[BREAKING]` | Updating the component would drop a connection or a saved value, or needs an input that nobody gave. | A field or output your flow has was removed or renamed, or an input that accepted `Message` and `Data` now accepts only `Message` and your flow connects a `Data` component to it. |
| `[BLOCKED]` | The component type no longer exists in this LFX build. | A bundle-only component is not installed in your environment. |
| `[CUSTOMIZED]` | Someone edited this component's code in the flow, or dismissed an update for it in the visual editor. `lfx upgrade --write` leaves it unchanged, and it makes the command fail only with `--strict`. | A component whose code was changed in the visual editor's code editor. |
| `[RETIRED]` | The component was retired and fails when the flow runs, even if someone edited its code in the flow. The line names the release that retired it and its replacement. `lfx upgrade --write` leaves it unchanged, and the command exits non-zero. | Chroma DB, retired in 1.13.0, replaced by the Knowledge component. |

To apply fixes or enforce stricter checks, run:

```bash
# Apply all safe upgrades and overwrite the file
lfx upgrade my-flow.json --write

# Fail if any safe upgrades are still pending or any component is customized (use after a dry run before running `--write`)
lfx upgrade my-flow.json --strict
```

## Inline compatibility checking with `--upgrade-flow`

Both `lfx run` and `lfx serve` accept an `--upgrade-flow` option so you can apply compatibility checks at execution without a separate `lfx upgrade` step.

```bash
# Check only: fail unless every component is up to date
lfx run my-flow.json --upgrade-flow=check "Hello world"

# Apply safe upgrades in memory, then run
lfx run my-flow.json --upgrade-flow=safe "Hello world"

# Same options for serve
lfx serve my-flow.json --upgrade-flow=safe
```

| Mode | Behavior |
|---|---|
| `check` | Reports compatibility issues and exits non-zero unless every component is up to date. No changes are written to disk. |
| `safe` | Applies all safe upgrades in memory, then runs or serves the flow. Customized components run as saved. Breaking, blocked, and retired components cause a non-zero exit, and so do customized components when `LANGFLOW_ALLOW_CUSTOM_COMPONENTS=false`, because their edited code cannot run. To fix that, allow custom components with `LANGFLOW_ALLOW_CUSTOM_COMPONENTS=true`, or update the component in the visual editor to use the current code, which discards the edits. |

## Pin versions

Pin `lfx~=1.14.0` in `requirements.txt` to track all patch releases for a given Langflow minor without crossing into the next minor automatically.

```text
# requirements.txt — allows 1.14.1, 1.14.2, … but not 1.15.0
lfx~=1.14.0
```
