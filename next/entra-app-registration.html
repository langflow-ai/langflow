Configure Langflow for Microsoft Entra

Connect Microsoft 365 to Langflow with an app registration you create in Microsoft Entra, which Langflow stores on the Langflow server. Each person then connects their own account in Langflow Settings.

To create the registration, see Register an application with the Microsoft identity platform.

Prerequisites​

  • A Microsoft Entra tenant, with permission to register an application.
  • Microsoft 365 licenses for users to connect. For each workload you must enable the following actions:
    • SharePoint Online and OneDrive for file actions.
    • Exchange Online for Outlook mail and calendar actions.
    • Microsoft Teams for chat and channel messages.
  • The directory or tenant UUID.
  • The public URL of the Langflow instance that hosts the OAuth callback.
  • Access to set LANGFLOW_CONNECTION_OAUTH_REGISTRATIONS on the Langflow server.

Connect Microsoft 365​

To connect Microsoft 365, do the following:

  1. In Microsoft Entra, copy the directory (tenant) ID and the application (client) ID from your registered single-tenant application. Langflow accepts one tenant per registration.

  2. Add Langflow's redirect URI to the Microsoft Entra registration. Use the same hostname in the browser and in the URI. For more information on adding a redirect URI in Microsoft Entra, see Redirect URI (reply URL) restrictions.

  3. In Microsoft Entra, add the delegated permissions for the actions you use with offline_access. Use the short names in Delegated permissions. For more information, see Configure a client application to access web APIs.

  4. In Microsoft Entra, create a client secret or a certificate. For more information, see Add credentials to your application.

    • If you're creating a client secret, copy the secret when Entra displays it.
    • If you're creating a client certificate, copy the private key and the certificate's SHA-256 thumbprint.
    • If you're creating a Desktop client, no secret is required.

For more information, see Public and confidential client apps.

  1. On the Langflow server, set the LANGFLOW_CONNECTION_OAUTH_REGISTRATIONS environment variable . Its value is the JSON below, not a path to a JSON file.

    {
      "microsoft-work": {
        "provider": "microsoft",
        "owner": "customer",
        "context": "self_managed",
        "client_type": "confidential",
        "tenant": "00000000-0000-0000-0000-000000000000",
        "client_id": "YOUR_APPLICATION_CLIENT_ID",
        "client_secret": "YOUR_CLIENT_SECRET",
        "redirect_uri": "https://langflow.example/api/v1/connections/oauth/microsoft/callback",
        "scopes": ["Mail.Read", "Calendars.Read", "Files.Read", "offline_access"]
      }
    }
    • Set LANGFLOW_CONNECTION_OAUTH_CONTEXT to the same value as context: self_managed, hosted, or desktop.
    • Replace YOUR_APPLICATION_CLIENT_ID, YOUR_CLIENT_SECRET, and tenant with the values from the registration.
    • Replace langflow.example with your instance's public hostname.
    • For a certificate, set private_key and certificate_thumbprint instead of client_secret.
    • For Desktop, set client_type to public and omit the secret. scopes is the list of permissions a person can consent to.

  2. Restart Langflow.

  3. In the Langflow header, click your profile icon, and then select Settings.

  4. Click Connections.

  5. Click Add connection.

  6. Select Microsoft 365. Enter a handle, such as work, and a display name.

  7. Under Scopes to request, select the permissions your flows need, and then click Continue.

  8. Complete consent. The consent prompt displays the permissions you selected.

  9. For a scheduled or deployed flow run, click Actions on the connection and select Allow scheduled and deployed runs.

If Microsoft Entra requests administrator approval, an administrator must approve the app before consent can complete. For more information, see Configure how users consent to applications.

If an administrator changes client ID, scope, or redirect URI, each user must reconnect to Langflow. To reconnect, click Settings, open the connection's Actions menu, and click Reconnect. Microsoft Entra will display the consent prompt again.

Rotating Entra secrets doesn't require reconnection.

Revoke an account connection​

To disconnect an account in Langflow, select Actions on the connection, and then click Revoke. Langflow deletes the stored credentials. To remove the Langflow app's access in Microsoft Entra, see Review permissions granted to applications.

Redirect URIs​

In Microsoft Entra, add the redirect URI that matches how you run Langflow. Use the Web platform for a hosted or self-managed server, and Mobile and desktop applications for Langflow Desktop. A headless run doesn't use a redirect.

ContextPlatformRedirect URI
Hosted or self-managed serverWebhttps://YOUR_​INSTANCE/api/v1/connections/oauth/microsoft/callback
DesktopMobile and desktop applicationshttp://localhost:7860/api/v1/connections/oauth/microsoft/callback
HeadlessNot applicableNo redirect. For how to supply a token, see Headless and CLI runs.

Replace YOUR_INSTANCE with the public hostname of the Langflow instance.

Delegated permissions​

In Microsoft Entra, add a Microsoft Graph permission for each action your flows use. These permissions don't require admin consent. For more information, see Configure how users consent to applications.

ComponentDelegated permission
Outlook: Send MailMail.Send
Outlook: Search MailMail.Read
Outlook Calendar: List EventsCalendars.Read
Outlook Calendar: Create EventCalendars.ReadWrite
Teams: Post Chat MessageChatMessage.Send
Teams: Post Channel MessageChannelMessage.Send
SharePoint/OneDrive: List ItemsFiles.Read
SharePoint/OneDrive: Fetch ItemFiles.Read

The Fetch Item action also requires Files.Read.All when you supply a Drive ID, and Sites.Read.All when you supply a Site ID.

Include offline_access in registration and in scopes. Without offline_access, Entra doesn't issue a refresh token, so the connection stops working after about an hour. A refresh token that isn't used for 90 days expires, and the user has to reconnect Langflow. For more information, see Refresh tokens.
