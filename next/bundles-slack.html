Slack

Bundles contain custom components that support specific third-party integrations with Langflow.

This page describes the components that are available in the Slack bundle.

Every Slack component runs on the Slack Web API and takes its credential from a Langflow connection rather than from a token pasted into the flow.

tip

If you installed lfx directly (not as part of langflow), install the Slack bundle separately:

  1. Run uv pip install lfx-slack.
  2. Restart Langflow.
  3. To confirm the bundle loaded, run lfx extension list.

If you installed Langflow with uv pip install langflow, these bundle components are already included.

For more information, see Install LFX with bundle components.

Two executing identities​

Slack has two kinds of token, and a component is fixed to one of them:

IdentityAuthorization profilePosts asAvailable on Desktop
Connected Slack userslack-user-oauththe person who authorized the connectionYes
App bot userslack-bot-installthe app's bot userWith a pasted bot token (xoxb-); not through Slack sign-in

Slack user scopes and bot scopes share names — chat:write is both a User Token Scope and a Bot Token Scope — so the scopes a connection was granted cannot tell the two identities apart. Each component instead checks the identity recorded on the connection and the token's own type prefix (xoxb- for a bot token, xoxp- for a user token), and fails with a connection authorization error, before any request reaches Slack, when either one names the wrong kind.

A headless connection supplied through LF_CONNECTION__SLACK__<NAME> has no recorded identity, so its token must carry a recognizable Slack prefix; a token without one is refused.

Langflow Desktop cannot install a bot through Slack sign-in, because Slack desktop redirects use PKCE and may not request bot scopes. On Desktop, install your own Slack app to the workspace, copy its Bot User OAuth Token (xoxb-), and add it under Settings > Connections > Add connection > Paste a token.

Langflow checks pasted bot tokens with Slack before saving and records the scopes Slack reports. Check credential checks the token with Slack again. If Slack rejects a pasted bot token during a check or a flow run, the connection becomes expired and unhealthy. App-level Socket Mode tokens (xapp-) are checked only by the listener when it opens a socket, so their credential health remains unknown in Settings.

Prerequisites​

  • A Slack app installed in the target workspace, and a Langflow connection for it. See Connections to connect the account, and Configure connection OAuth for the registration steps, the redirect URLs, and the per-action scope tables.
  • For bot components, the app's bot user must be a member of the channel it acts on.

Slack: Search (as user)​

Calls search.messages with the connected user's visibility. Accepts the same query modifiers as the Slack search bar, such as in:#general from:@avery.

Required scope: search:read.

Outputs a list of Data objects, one per match, and a Pagination Data carrying Slack's result counts and the next_cursor for the following page.

Slack: Read Thread (as user)​

Calls conversations.replies for one thread, identified by its channel and the parent message's ts.

Required scopes: channels:history, groups:history, im:history, mpim:history. All four are requested so one connection can read threads in public channels, private channels, DMs, and group DMs.

Outputs the thread's messages as Data objects and a Pagination Data with has_more and next_cursor.

important

For apps that are distributed but not listed in the Slack Marketplace, Slack rate-limits conversations.replies to one request per minute and caps each page at 15 messages. Marketplace-listed apps get Tier 3 (50+ per minute). A customer-owned app used only inside its own workspace is not affected.

Slack: Send Message (as user)​

Calls chat.postMessage with the user token, so the message is attributed to the connected person.

Required scope: chat:write.

Set Thread timestamp to reply inside a thread. Optional Blocks accepts Block Kit blocks as Data objects. Slack truncates message text above 40,000 characters, so the component rejects longer text before sending.

Outputs a Data with the channel, ts, and the stored message.

Slack: Create Canvas (as user)​

Calls canvases.create with markdown content, up to 1 MiB. The canvas is owned by the connected user.

Required scope: canvases:write.

Set Channel ID to add the canvas as a channel tab. This field is required on free Slack plans.

Outputs a Data with the new canvas_id.

Slack: Post Message (as app)​

Calls chat.postMessage with the bot token, so the message is attributed to the app's bot user rather than to a person.

Required scope: chat:write (bot).

Adds Also send to channel (reply_broadcast) and Attachments on top of the user variant's inputs.

Slack: Add Reaction (as app)​

Calls reactions.add as the bot user. Give the emoji name without colons, such as thumbsup.

Required scope: reactions:write.

Slack: List Channel Members (as app)​

Calls conversations.members as the bot user.

Required scope: channels:read. Two scopes are requested only when you enable the matching option:

OptionAdditional scope
Private channelgroups:read
Resolve display namesusers:read

With Resolve display names off, the component returns member IDs. With it on, it calls users.info once per member and returns the name, real name, display name, and bot flag as well — which costs one extra request per member, so leave it off for large channels.

Outputs the members as Data objects and a Pagination Data with next_cursor.

Slack triggers​

A trigger runs its flow when something happens in Slack. Add one to a flow, choose its Slack connection, save the flow, and then enable the trigger.

How events reach Langflow​

Slack delivers events in two ways. Langflow picks one from the connection you choose on the trigger, so the flow never names a transport, and the same flow runs unchanged on hosted Langflow, a self-managed instance, and Desktop:

Connection on the triggerTransportWhere it works
A Slack app installation (Sign in with Slack, bot)Events API: Slack posts each event to your Langflow over HTTPSHosted, and self-managed instances Slack can reach
An app-level token (Paste a token, xapp-)Socket Mode: Langflow opens a WebSocket to Slack and holds itSelf-managed instances Slack cannot reach, and Desktop

Hosted Langflow uses the Events API only: its Slack app is listed in the Slack Marketplace, and Marketplace apps cannot use Socket Mode. Desktop uses Socket Mode only, because Slack has no way to reach a computer. If you choose a connection the deployment cannot use, the trigger says why and stays unarmed.

Both transports hand the flow the same data for the same event, and a Slack event runs its flow once even when Slack retries the delivery.

They differ in one way: which workspaces a trigger hears. An Events API trigger hears only the workspace its installation belongs to. An app-level token belongs to the whole app, so a Socket Mode trigger hears every workspace the app is installed in. Use Channel IDs to narrow it.

Slack: On Message​

Runs the flow when someone posts where the app can see it: in a public channel, a private channel, a direct message with the app, or a group DM. The app's own messages never trigger it, so a flow that replies in the thread doesn't trigger itself.

InputDescription
Slack ConnectionThe connection the trigger listens through. It decides the transport.
Only when the app is mentionedFire only for messages that @-mention the app.
Channel IDsFire only in these conversations, by ID, such as C0123456789. Find a channel's ID at the bottom of its details. Leave empty for every conversation the app can see.
Conversation typeschannel (public), group (private), im (direct message), mpim (group DM). All four by default. Hidden and reset to all four when Only when the app is mentioned is on, because Slack mention events do not include a conversation type.
Include thread repliesOn by default.
Include messages from other botsOff by default.
Include edits and deletionsOff by default. When on, the event's subtype is message_​changed or message_​deleted.

Outputs the event as Data and its text as a Message, ready to connect to an agent.

Slack: On Reaction​

Runs the flow when someone adds or removes an emoji reaction on a message.

InputDescription
Slack ConnectionThe connection the trigger listens through.
EmojiEmoji names without colons, such as rocket. Leave empty for any reaction. A skin-toned reaction matches its emoji.
Channel IDsFire only in these conversations. Leave empty for every conversation.
Fire when a reaction isadded (default), removed, or both.

What the flow receives​

The trigger's Event output is a Data object. Its payload has the same keys for every Slack event, with null where a key does not apply:

KeyDescription
typemessage, app_​mention, reaction_​added, or reaction_​removed.
channel_​id, channel_​typeThe conversation, and its kind for messages.
user_​id, text, tsWho posted (or reacted), the message text, and the message timestamp.
thread_​ts, is_​thread_​replySet when the message is a reply in a thread.
reaction, item_​ts, item_​user_​idThe emoji, and the message it was added to.
session_​keyslack:{team}:{channel}:{thread_​ts or ts}, the conversation the run belongs to. {team} is the workspace of the app installation that received the event, so a thread in a channel shared with another workspace stays one session whichever side replies.
slack_​event_​id, team_​id, api_​app_​id, event_​timeSlack's identifiers for the event. In a shared channel, team_​id can name the other workspace.
eventSlack's original event object, for anything the other keys leave out.

Every run started by a Slack event uses the conversation as its session: each reply in a thread lands in the thread's session, so an agent keeps the whole thread as memory. Three replies to one thread start three runs that share one session. A reaction's session is the message it was added to.

To reply in the thread, pass channel_id and thread_ts (or ts, for a top-level message) to Slack: Post Message (as app).

Set up a Slack app for triggers​

Create the app from one of these manifests (Create New App > From a manifest), and then replace the placeholders:

  • Events API manifest: replace LANGFLOW_HOST with your Langflow's public host, and REGISTRATION_ID with the name of the app's registration in LANGFLOW_CONNECTION_OAUTH_REGISTRATIONS.
  • Socket Mode manifest: no URL is needed.

Both manifests subscribe the bot to message.channels, message.groups, message.im, message.mpim, app_mention, reaction_added, and reaction_removed, and request these bot scopes, which also cover the as app actions:

Bot scopeUsed for
app_​mentions:readMentions of the app
channels:historyMessages in public channels
channels:readSlack: List Channel Members (as app)
chat:writeSlack: Post Message (as app)
groups:historyMessages in private channels
groups:readPrivate channels in Slack: List Channel Members (as app)
im:historyDirect messages with the app
mpim:historyGroup DMs
reactions:readReactions
reactions:writeSlack: Add Reaction (as app)
users:readDisplay names in Slack: List Channel Members (as app)

A trigger on the Events API also needs the scopes for what it listens to: a message trigger needs the *:history scope of each conversation type it covers (or only app_mentions:read when it fires only on mentions), and a reaction trigger needs reactions:read. Enabling a trigger whose installation lacks them says which are missing. So does saving the flow when the save moves an enabled trigger to another connection or widens what it listens to: the trigger stops, with the reason, until the scopes are there.

Events API (hosted and reachable self-managed instances)​

  1. Under Basic Information, copy the app's Signing Secret into the registration's signing_secret, next to its client_id and client_secret:

    {"slack-app": {"provider": "slack", "profile": "bot", "client_id": "...", "client_secret": "...",
     "signing_secret": "...", "redirect_uri": "https://LANGFLOW_HOST/api/v1/connections/oauth/slack/callback",
     "scopes": ["chat:write", "channels:history", "..."]}}

  2. Under Event Subscriptions, set the Request URL to https://LANGFLOW_HOST/api/v1/triggers/ingress/slack/apps/slack-app, where the last segment is the registration name. Slack verifies the URL immediately; Langflow answers as soon as the registration is configured, before any trigger exists.

  3. In Langflow, add a Slack connection with Sign in with Slack and the bot identity, and choose it on the trigger.

One Request URL serves every workspace the app is installed in. Each event reaches only the triggers whose connection is an installation in that workspace. Triggers can't use an org-wide Enterprise Grid installation, which belongs to no single workspace. Install the app to a workspace instead.

Socket Mode (Desktop and instances Slack cannot reach)​

  1. Under Basic Information > App-Level Tokens, generate a token with the connections:write scope.
  2. Under Install App, install the app to your workspace and invite it to the channels it should hear.
  3. In Langflow, go to Settings > Connections > Add connection, choose Slack and Paste a token, and paste the app-level token (xapp-). To reply from the flow, add the Bot User OAuth Token (xoxb-) the same way, as a second connection.
  4. Choose the app-level token connection on the trigger.

An app-level token only opens Socket Mode connections. Langflow uses it only in the trigger listener process, never in a flow, so choosing it on an action component fails. Socket Mode isn't available on hosted Langflow.

important

An app-level token is the app's whole event stream: every workspace the app is installed in, every conversation it can see. When several people on one Langflow instance each add a token for the same Slack app, Langflow delivers each of the app's events to all of their Socket Mode triggers, because Slack spreads an app's events across every open connection. Give an app-level token only to people who may read everything the app can see.

Allow background runs​

A trigger runs its flow with no one signed in. The connection on the trigger, and every connection the flow uses, must allow that: turn on Allow background runs when you add the connection, or on the connection later. Enabling a trigger whose connection doesn't allow background runs says so.

Troubleshoot triggers​

The trigger won't enable. Its error says what is missing: a connection, the flow owner's own connection (triggers can't use shared or instance connections), a registration signing secret, a scope, or background-runs consent.

Slack says the Request URL did not respond. Check that the registration named in the URL exists, has signing_secret, and that LANGFLOW_CONNECTION_OAUTH_CONTEXT matches the registration's context.

The flow never runs for a message. Invite the app to the channel. Check the trigger's filters: channel IDs, not names, and whether it fires only on mentions. Messages posted by the app itself never trigger it.

A Socket Mode trigger stays silent. Check that the listener process is running (LANGFLOW_LISTENERS_MODE=subprocess, or langflow listeners) and that Socket Mode is turned on in the app's settings.

Errors​

Slack reports application-level failures as HTTP 200 with {"ok": false, ...}. The bundle translates those into Langflow's integration error codes, so the canvas shows an actionable message instead of a generic provider outage:

Slack errorLangflow errorWhat to do
invalid_​auth, token_​expired, token_​revoked, account_​inactive, not_​authedauth-expiredReconnect the connection.
missing_​scopescope-missingGrant the listed scopes and reconnect.
ratelimitedrate-limitedRetry after the reported interval.
channel_​not_​found, not_​in_​channelinvalid-requestCheck the channel ID, and invite the app to the channel (or join it, for actions that run as you).
Input errors such as invalid_​name, invalid_​blocks_​format, no_​text, thread_​not_​foundinvalid-requestFix the component's inputs. Retrying with the same inputs fails again.
Workspace or admin denials such as restricted_​action, team_​access_​not_​granted, no_​permissionconnection-not-authorizedAsk a workspace administrator, or use a connection that is allowed to act.
not_​allowed_​token_​type, method_​not_​supported_​for_​channel_​typeaction-unsupportedUse a different component, channel type, or plan.

If Slack rejects a token, the component re-resolves the connection once and retries. That is how a rotated Slack token is picked up: Slack tokens do not expire unless the app opted into token rotation, so a rejection is the only signal.
